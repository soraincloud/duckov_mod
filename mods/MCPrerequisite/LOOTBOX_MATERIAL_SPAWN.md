# MC 共享材料地图容器刷新说明

本文档说明 `MCPrerequisite` 中关于 `玻璃`、`铁粒`、`铁锭`、`铁块`、`金粒`、`金锭`、`金块` 在地图容器随机物品刷新中的实现方式与当前概率设置。

## 作用范围

当前逻辑只作用于地图中的普通容器随机刷新流程，也就是挂载了 `LootBoxLoader` 的地图容器。

不影响以下内容：

- 商人售卖清单
- 工作台配方
- 玩家主动丢弃物品
- 角色死亡掉落箱
- 其他 mod 自己手动往容器里塞物品的逻辑

## 当前实现方法

实现位置：`mods/MCPrerequisite/MaterialItemRegistry.cs`

当前做法不是直接重写原版容器的随机掉落表，而是在地图关卡初始化完成后，以及运行时定期刷新时：

1. 查找场景中的 `LootBoxLoader`
2. 读取其对应 `InteractableLootbox` 的 `Inventory`
3. 保留原版容器已经生成好的随机物品
4. 额外进行一次 MC 材料注入判定
5. 若命中，则向容器中补入 `1` 个共享材料物品

这样做的目的：

- 不破坏原版容器已有随机池
- 不需要改场景资源或预制体
- 可以直接通过前置 mod 在运行时统一生效
- 概率和材料种类都可以只在前置里集中维护

## 注入规则

每个地图容器最多额外补入 `1` 个 MC 共享材料物品。

如果该容器已经包含以下任意一种共享材料，则不会重复再补：

- `玻璃`
- `铁粒`
- `铁锭`
- `铁块`
- `金粒`
- `金锭`
- `金块`

如果容器已满，当前实现会先把容器容量加 `1`，再尝试放入该材料。

## 当前概率

当前按顺序进行判定，满足：

- `玻璃` 仍然是最常见基础材料
- `铁粒`、`金粒` 略高于对应的锭类材料
- `铁块`、`金块` 明显低于粒和锭

- `玻璃`: `16%`
- `铁粒`: `10%`
- `铁锭`: `8%`
- `铁块`: `2%`
- `金粒`: `7%`
- `金锭`: `5%`
- `金块`: `1%`
- 未命中任何 MC 材料: `51%`

换句话说，单个容器触发额外 MC 材料补入的总概率为：

`16% + 10% + 8% + 2% + 7% + 5% + 1% = 49%`

## 当前相关常量

当前常量定义在 `MaterialItemRegistry.cs` 中：

- `LootBoxGlassChance = 0.16f`
- `LootBoxIronNuggetChance = 0.10f`
- `LootBoxIronIngotChance = 0.08f`
- `LootBoxIronBlockChance = 0.02f`
- `LootBoxGoldNuggetChance = 0.07f`
- `LootBoxGoldIngotChance = 0.05f`
- `LootBoxGoldBlockChance = 0.01f`

如果后续想调整刷新率，直接改这三个值即可。

## 设计意图

当前概率设计是为了满足：

- `玻璃` 作为最常见基础材料，仍然保持最高刷新率
- `铁粒`、`金粒` 作为更零散的材料，略高于对应的锭类
- `铁锭`、`金锭` 作为中间档材料，低于粒类、高于块类
- `铁块`、`金块` 作为压实材料，在地图容器中的出现率应明显更低

如果后续需要更贴近玩法节奏，可以按以下方向调整：

- 想让基础材料更常见：提高 `玻璃`、`铁粒`、`金粒` 概率
- 想让中期制作更顺滑：适度提高 `铁锭`、`金锭` 概率
- 想让压实材料更稀有：继续降低 `铁块`、`金块` 概率
- 想让整体容器更常见地刷出 MC 材料：同时提高全部材料概率总和

## 备注

当前地图容器材料注入和地上掉落显示大小调整，都是由 `MCPrerequisite` 统一托管。后续若继续新增共享 MC 材料，建议也在本前置中统一补充此文档，避免概率和实现分散在多个 mod 中。
